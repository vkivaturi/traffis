# BL-1 Loop — SUMO XML & Route Specification

This document provides the complete blueprint for building all SUMO network, connection, route, and scenario configuration files for **BL-1** in `backend/sumo_config/scenarios/bl_1/`.

---

## 1. Design Constraints & Conventions

1. **No Traffic Signals**: Every internal junction uses `type="priority"` (or `type="right_before_left"` / `priority` with explicit connection `pass="true"` where streams merge without cross-cutting). No `traffic_light` nodes exist.
2. **All Sections Are 3-Lane Roads**: Every edge has `numLanes="3"`, `width="3.2"`, default speed `13.89` m/s (`50 km/h`), and `spreadType="center"` (or explicit offset `shape` where opposing carriageways share a corridor).
3. **Left-Hand Traffic (LHT)**: Set `<lefthand value="true"/>` in `bl_1.netccfg` (matching `gnt_circle.netccfg`).
4. **Whiteboard Section ID Disambiguation**:
   - **`4` appears twice on the whiteboard**:
     - `sec_4_shl`: Westbound outbound road to `SHL` (used in `THB -> SHL`).
     - `sec_4_nb`: Northbound inner link from `sec_15` to `sec_8` (used in `MIN -> HIT`).
   - **`23` does not exist** on the whiteboard.
   - **`16` exists** on the whiteboard (Eastbound between `sec_2/3` and `sec_17/24`) and should be defined in `bl_1.edg.xml` for geometric completeness even though no current O-D route uses it.

## 2. Files to Create

```text
backend/sumo_config/scenarios/bl_1/
├── bl_1.nod.xml      # Junction & terminal nodes
├── bl_1.edg.xml      # All 25 directed 3-lane road sections
├── bl_1.con.xml      # Explicit lane-to-lane connections (prevents unwanted U-turns/crossings)
├── bl_1.netccfg      # netconvert configuration (lefthand=true, no TLS)
├── bl_1.net.xml      # Compiled network (generated by netconvert)
├── bl_1.rou.xml      # Vehicle types + all 19 O-D routes + flows
├── bl_1.sumocfg      # Master SUMO config
└── scenario.xml      # Traffis runtime demand, behaviour & vehicleMix config
```

## 5. Explicit Connections (`bl_1.con.xml`)

Use `<no-turnarounds value="true"/>` in `bl_1.netccfg` and declare explicit edge-to-edge connections in `bl_1.con.xml` so vehicles only take valid whiteboard movements (no U-turns, no cross-cutting):

- `sec_1` → `sec_2`
- `sec_20` → `sec_2`
- `sec_2` → `sec_3` (and optionally `sec_16`)
- `sec_3` → `sec_4_shl`, `sec_6`
- `sec_5` → `sec_6`
- `sec_6` → `sec_7`, `sec_8` (via `j_hit_merge` or direct), `sec_10`
- `sec_4_nb` → `sec_8`
- `sec_9` → `sec_10`
- `sec_10` → `sec_12`, `sec_14`
- `sec_11` → `sec_12`, `sec_14`
- `sec_13` → `sec_14`
- `sec_14` → `sec_24`, `sec_15`, `sec_17`
- `sec_15` → `sec_4_nb`
- `sec_25` → `sec_17`
- `sec_17` → `sec_18`, `sec_19`
- `sec_18` → `sec_20`, `sec_21`
- `sec_19` → `sec_22`

## 6. Network Compilation (`bl_1.netccfg`)

```xml
<configuration>
    <input>
        <node-files value="bl_1.nod.xml"/>
        <edge-files value="bl_1.edg.xml"/>
        <connection-files value="bl_1.con.xml"/>
    </input>
    <output>
        <output-file value="bl_1.net.xml"/>
    </output>
    <processing>
        <lefthand value="true"/>
        <no-turnarounds value="true"/>
        <geometry.avoid-overlap value="true"/>
        <junctions.corner-detail value="5"/>
    </processing>
</configuration>
```

Compile with:
```bash
netconvert -c backend/sumo_config/scenarios/bl_1/bl_1.netccfg
```

### 7.1 `scenario.xml` Template
Follow `gnt_circle/scenario.xml` so `backend/app/scenarios/settings_loader.py` can load `bl_1` dynamically:
- `<scenario id="bl_1" maxSimTime="300">`
- `<demand>`: one `<od key="..." vehsPerHour="..."/>` for each of the 19 O-D keys above.
- `<behaviour>`: `Krauss` + `SL2015` (`lateralResolution="0.8"`), with `departLane="best"` / `departSpeed="max"` in `bl_1.rou.xml` flows so all 3 lanes are utilized smoothly.
- `<vehicleMix>`: e.g. `car` (`0.80`), `van` (`0.15`), `sports` (`0.05`).
